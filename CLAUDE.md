# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A story/content generator for the `stratum-if` interactive-fiction engine, which is room-based (rooms, fixtures, characters with topics; not a choose-your-own-adventure). A user supplies a short free-text story premise (a **kernel**), and a multi-step LLM pipeline analyzes it and expands it, with no further user involvement, into a second-person story.

What is built today ends at an **outline**: a story graph of **nodes** (one framework beat filled on one line: a short summary, one image, where, who), **lines** (through-lines: a motivation, a strategy, an ending with the world it leaves, a path of nodes), plain-language **branch triggers**, and rough **character and location registers**. The pipeline is: step 2 (rating filter + shape split), phase 3 (nine blind extractions + 3h cross-check + a computed constraint map and story brief), 3.4 genre promises (what the audience expects, as defaults), 3.5 premise (the dramatic engine, built in three calls, audited, repaired), 3.8 story form (a framework chosen from a computed shortlist), step 4, the outline loop (main line, a branch plan, then one divergent line per iteration), which produces `stories/<id>/<id>_story.json` and `.md`, and 4e, a computed evaluation plus one cheap reading call that reports quoted, checked facts (`<id>_eval.json`). After the outline, **stage A** (`generator/arcs.py`, `--stage-a`) maps the characters' arcs onto the graph and expands it with minor nodes (opportunities that move named arc states, revelations, demonstrations, resolutions), with the structure, thresholds and checks in Python (`<id>_arcs.json`, `.md`). **Stage B** (`generator/world.py`, `--stage-b`) builds the world as engine data: characters with curated topics and talk about anything encountered, rooms and objects, the map, and "you" (`<id>_world.json`, `.md`). **Stages C and D** (`generator/compile_scenes.py`, `--stage-d`) compile each scene into engine data and assemble `<id>_package.json`, playable with `engine/cli.py`, checked by the engine's validator and playtest. **The prose stage** (`generator/prose.py`, `--prose`) revises the package's text in one voice per story: a style sheet with a sample paragraph (8a, checked by 8v), then each scene, person, location and the frame edited by id (8b), with names turned into codes the engine renders by what the player knows (`<id>_package_prose.json`); design and decisions in `docs/later_stages.md` §6. `prompts/later/` + `generator/later/` hold parked material.

`docs/outline_design.md` is the live design document. `docs/fable_response_5.md` explains the 2026-10-04 quality pass (promises, events, voices, the branch plan, the evaluation harness) and holds the current first-live-run checklist; `docs/fable_response_4.md` explains why the loop has the shape it has. `docs/kernel1_target_outline.md` is a hand-written example of a right-sized outline (never paste it into a prompt). `docs/step4_design.md` and `docs/strategy.txt` are historical. The project has no test framework or linter; the prompts are the main thing being iterated on.

**Hard constraint: production inference is a local 27B-class thinking model via Ollama.** Nothing in the runtime path may assume a frontier model. The real limits are wall-clock time per call and trace size per call, and trace size is a function of what a call is given and asked to return, not of instructions about how to reason.

## Setup and running

```
python -m venv .env
pip install -e .
```

The LLM backend is a local Ollama server. `main.py` calls `dynamic_config.get_client()`, which must return an `LlmClient` subclass; create `generator/dynamic_config.py` locally (see README for a template); it is gitignored. `STRATUM_CLIENT=stub` selects `generator/stub_client.py` (a model-free client that answers every prompt with schema-valid canned JSON) and needs no `dynamic_config.py`.

All scripts use sibling-module imports, so **run from inside `generator/`** (the test script can be run from anywhere):

```
python tests/test_plumbing.py                                           # stub-driven plumbing tests, ~20 s; run before any model time
python tests/test_engine.py                                             # engine tests, ~25 s
cd generator
python probe_ollama.py                                                  # what the local server supports (thinking, schemas, breakers, speed)
python main.py --story-id=kernel1 < ../tests/kernels/kernel1.txt      # one kernel, whole pipeline
python main.py --story-id=foo --rating=PG-13 --stop-after=3.5 < k.txt  # rating filter; stop after 2 | 3 | 3.4 | 3.5 | 3.75 | 3.8
python main.py --story-id=kernel1 --max-iterations=2 < ...            # cap the outline's lines (default: from the ending tier, 1-6, +2 when linear)
python main.py --story-id=kernel1 --branching=judge --no-promises < ... # the pre-2026-10-04 behaviour (4d per iteration, no 3.4), for A/B
python report.py kernel1 --baseline ../docs/baseline_kernel1_run_stats.json   # per-stage time and trace size against the archived run
python ab.py run --variant plan --kernels eval -- --branching=plan    # replay 3.4 onward from saved phase 3 into stories/<kernel>_plan/
python ab.py compare --variants plan,judge --kernels eval             # the computed metrics and judge scores side by side
./todo.sh                                                             # all 35 test kernels
python batch.py add kernel38,kernel39 && python batch.py run            # the batch queue: one job on the GPU at a time, resumable
python batch.py add --set quick --variant plan -- --branching=plan    # a variant over an evaluation set (replays 3.4 on)
python batch.py status; python batch.py report                        # progress; times, outcomes and metrics
STRATUM_CLIENT=stub python main.py --story-id=stubtest < ../tests/kernels/kernel1.txt
python main.py --story-id=kernel1 --stage-a < ../tests/kernels/kernel1.txt   # also stage A (replays everything already saved)
python arcs.py kernel35_f5                                             # stage A alone, on an outline made by older code
python scenes.py kernel35_f5                                           # stage B0: scenes, subjects, the room target (no model)
python world.py kernel35_f5                                            # stage B: characters, places, conversation, you (needs stage A)
python compile_scenes.py kernel35_f5                                   # stages C and D: the engine package (needs A and B)
python ../engine/cli.py ../stories/kernel35_f5/kernel35_f5_package.json   # play it
```

Other flags: `--max-repairs` (3.5 repair rounds, default 2), `--framework=<id>` (skip the 3.8 choice), `--no-think-steps` / `--think-steps` (comma-separated prefixes, steps or step_names to run with thinking off / on, overriding the call's class), `--no-breakers`, `--no-force-answer` (skip budget forcing), `--craft-spine` (run the optional 3.75 craft spine), `--no-promises` (skip 3.4), `--branching=plan|judge` (how divergent lines are seeded), `--no-outline-judge` (skip the 4e reading call; the metrics still run). Environment: `STRATUM_SAMPLER=model` (send no sampler options), `STRATUM_PRESENCE_PENALTY`. Output goes to `stories/<story_id>/`. `stories/` is not gitignored; `*.log` is.

## Pipeline architecture

`generator/main.py` — `StoryGenerator`. `run_prompt(prefix, name, replacements, prompt_file=None, validator=None, klass='extract', schema=None)` is the one model call: it loads `prompts/<prompt_file or prefix_name>.prompt`, substitutes `$$PLACEHOLDER$$`s by plain string replace (a leftover placeholder raises), calls the client, saves `<prefix>_raw_input_prompt.txt`, `<prefix>_raw_output_thinking.txt`, `<prefix>_raw_output_response.txt` and the parsed `<prefix>_<name>.json`, appends a record to `<id>_run_stats.json`, and returns the parsed value. A `validator` can reject an answer; the call is retried once **with the complaint and the previous answer appended**. A saved file that fails the validator is reported as stale and named. JSON goes through `lenient_json_loads`.

**Call classes** (`generator/stats.py`): every call is `extract` (phase 3: untouched, no breaker), `classify` (thinking off, a rationale field first in the schema: s2 shape, 3.4, 3.5c, 3.8, 4e), `judge` (4p, 4d), `audit` (3.5k, 3.5v) or `build` (thinking on, with a target and a circuit breaker on thinking bytes and wall clock; a call over its thinking limit first gets its answer forced from the partial thinking; if that fails, or another breaker tripped, it re-runs once with thinking off; reasoning the client sees looping is cut at once and first re-run from a new seed, thinking on). Decide a new call's class before writing its prompt. `generator/schemas.py` holds the JSON schema for each new prompt (Ollama structured outputs); the client sends it on thinking-off calls by default. A validator may raise `SoftReject` (`generator/errors.py`): the answer is re-asked once with the complaint and accepted if it comes back the same, for quality rules that should cost one retry and never the run.

Order: `s1 → s2 (rating filter, shape split) → run_phase3()` (`s3_0a, s3_0b, s3_0c, s3b, s3c, s3d, s3e, s3f(←3d), s3g(←3-0a,3-0c), s3h(←bundle)`, then `build_constraint_map()` and `build_story_brief()`), then `run_promises()`, `run_premise_expansion()`, `run_story_form()`, `run_outline()`, `run_outline_judge()`.

**The content kernel.** Step 2 splits the kernel into `s2_kernel.txt` (content, verbatim minus shape clauses) and `s2_shape.json` (ending-count tier, linearity, choice density, length). Every later step reads the content kernel; the shape reaches only step 4, as advisory targets computed by `brief.shape_targets`. A stated ending number decides the tier by lookup.

**The brief.** `generator/brief.py` computes `s3_brief.json` (each phase-3 field's value and binding class; a constraint phase 3 inferred rather than read is marked `inferred` and rendered `[constraint, inferred]`: it still binds, but the prompts are told it is a floor the Kernel's details forced, never a ceiling on what the genre may add). Every prompt after 3h receives the brief, never the raw bundle, usually as `brief_lines()` (one line per field) or `brief_lite()`. Keep it that way: trace length scales with input size.

**Blind execution** is the default for phase 3; three steps are chained only because their field is undefined without the other's output. Never chain for agreement — that is 3h's job. Do not weaken phase 3.

**3.4 genre promises** (`s3_4_promises`, thinking off, about a minute): what a reader who asked for this kind of story expects and the Kernel left unsaid (promises, set pieces, the tone engine, obligatory cast, and `must_not`: what the Kernel rules out). Rendered by `brief.promises_lines()` into 3.5a, 3.5b, 4a and 4c as **defaults one rank below a brief default**: the Kernel's words and every brief constraint beat them; nothing audits the premise against them. `--no-promises` skips the step and the prompts get `none`.

**3.5 is the dramatic engine**, built in three calls: `s3_5a_engine` (protagonist with `cannot_do` and `ties` (people, never places), arena, pressure, opposition with `shown_by` (an early moment showing what it will do), `events`: two or three things the world brings about on its own schedule, `hidden_truth`, mediation, `price` (what the story takes for good on at least one line, separate from 3-0c's failure model, which bounds only how the player loses), `setups` (one or two plants paid at the crisis), `rules` (terms for any magic, bargain or mechanism); `StoryGenerator.craft_problems` soft-rejects a missing one), `s3_5b_turns` (3–5 turns, each a different form, each with `ways_through` and costs; at least one names the `set_piece` it delivers; when there are companions, one turn's ways differ in who is won, lost or turned), `s3_5c_cast` (one rough sketch per role the turns name: wants, holds, `edge`, `tie`, `voice` with one sample line, `breaking_point` for companions; every crowd has a representative). `premise_computed_findings()` checks what is a count or a lookup (events present, a set piece named when promises offered one, `example_guard.copied_phrases` for output copied from a calibration example; the step-4 validators run the same check); `with_echo_check` soft-rejects a lever, pressure, event or way that copies five or more words of the brief's own analytic text (`example_guard.brief_echoes`). `s3_5k_kernel_check` asks, clause by clause, whether the premise contradicts the Kernel, writing out what each clause commits to (who, when or in what order, how many, what it rules out) beside the premise's own words before the verdict; it is its own call because a Kernel contradiction is the one judgment that halts a run, and inside the full audit it missed subtle ones in 2 of 3 runs (2026-10-07). `s3_5v_premise_check` answers a fixed list of yes/no questions (constraints, engine checks) and searches for systems and losses, giving each entry a kind (`number`, `system`, `loss`, or `fiction`, which is dropped; a loss quoting the price or a rule's `if_broken` is the price by construction). Python checks every finding's quote against the premise (`verified`). Verified findings go to `s3_5r<n>_premise_repair`, numbered F1, F2, ...; it returns **only the sections it changed**, and may decline a finding that misreads a shared definition (never a Kernel clause), which is then `disputed` and not sent again. A repair that leaves a finding's quoted words (five or more) in a section it did not return gets one SoftReject retry, and the finding is carried into the next round even when that round's audit misses it (`unrepaired`; King, 2026-10-07: the log rewrote turn 5, the answer held only cast_seeds). Up to `--max-repairs` rounds. After the last one **only a computed structural check or a verified Kernel contradiction halts**; a `craft` finding (`craft_problems`: no price, no setup, rule terms that turn on paper, the opposition never shown; and a turn that retells another's way in the same words, `example_guard.repeated_ways`, also a SoftReject at 3.5b, which points at the earlier turn when the later is the last) goes to the repair and is a note after it (`PipelineHalt`, exit 2); every other finding is a judgment and is kept as a note in `accepted_with` (2026-10-06: in the saved runs the audit's quotes were real and every final-round halt was a real quote misread). Files: `s3_5_premise.json` (as built), `s3_5_premise_accepted.json` (what downstream reads), `s3_5_loop.json`.

**3.8 story form.** `config/frameworks.json` is the framework library (beats with jobs); `generator/frameworks.py` scores it against the brief and returns a shortlist of three and the modifiers the brief licenses; `s3_8_story_form` picks. The framework scaffolds beats only: it never drives how many lines or endings are built.

**Step 4** (`generator/outline.py`, `OutlineBuilder`): iteration 1 runs `s4a_main_line` (the through-line, an ending with its **world** (`answer`, `standing`, `lost`, `changed`, `pays_price`), and one entry per beat: `beat`, `turn`, `way`, `event`, `plants`, `pays` (setup numbers), `adapted`; at least one event placed, every setup planted before it is paid, soft; some line's ending pays the price, checked by 4p). Under `--branching=plan` (default) it then runs `s4p_branch_plan` once (judge class): every further line's seed at once, each with its trigger and ending world; the validator computes that no two seeds (or a seed and the main line) leave the same world and that one seed leaves in the main line's first half (both `SoftReject`). Iteration n runs `s4c_divergence` on the next planned seed (or, under `--branching=judge`, on `s4d_next_line`'s seed from the previous iteration); a seed 4c cannot build is dropped and the next is tried. Every iteration runs `s4b_line_nodes` (title, summary, `image`, where, who; registers grow as needed) and the computed checks (`generator/checks.py`). Structural rules are enforced by each call's validator; `check_story` reports broken invariants (should be none) and notes (`late_forks`, `repeated_node`, `repeated_situation`, `same_world`, `companions_static`, ...). Prefixes: `s4a_i1`, `s4p_i1`, `s4c_i<n>`, `s4b_i<n>`, `s4d_i<n>`. State is rebuilt by replaying the driver over saved files, so a rerun makes no model calls. `--max-iterations` defaults to the Kernel's ending tier (one 1, few 2, several 4, many 6, unstated 3; a linear shape gets two more).

**4e evaluation** (`generator/evaluate.py`): computed metrics over the finished outline (fork positions, distinct ending worlds, companions whose standing varies, events placed, set-piece turns, promise coverage, repeated phrases, retold situations, summary size) plus one thinking-off call, `s4e_outline_judge`, that READS rather than scores: what is lost for good and what kind of thing (person, body, bond, thing, place, way of life, or only a feeling), plants and payoffs, the opposition at work, a reversal, errands, abstractions and craft the outline only announces ("the cost is..."), each with a quote Python checks against the node it names, plus the best and worst thing. The checked counts are `judge.facts` in `<id>_eval.json`. It used to score six axes out of 5; those totals tracked polish and noise and credited announced craft (2026-10-06), so nothing should be decided on a single judge number again. `generator/compare.py` (4f) compares two outlines on six questions, asked in both orders, a win counted only when it holds both ways; `--main-line` for the linear human references. `generator/ab.py` replays 3.4 onward from a story directory's saved phase 3 into `stories/<kernel>_<variant>/` and tabulates variants side by side; `tests/kernels/EVAL_SET.txt` is the fixed evaluation set.

**Re-running a step**: delete its saved output file(s). For the 3.5 loop, delete every `s3_5*` file (a finished loop replays its accepted premise as saved, without re-running today's checks over it). A rejected attempt's output is kept as `<prefix>_raw_output_*_rejected_<n>.txt`. Downstream outputs are not invalidated automatically — delete them too when an input changed. Each story directory carries `<id>_pipeline.json` (schema version 5); a directory from an older schema stops the run and prints what to delete (phase-3 outputs may be kept).

## Prompts

**Shared definitions** live in `prompts/terms.txt` (PRICE: losing versus the price; ENGINE: what a system the engine lacks is; PICTURE; RULES: terms as conduct, `if_broken` as price; BEINGS: person, dead, animal, creature, thing). A prompt writes `$$TERM_PRICE$$` and `load_prompt` puts the section in (`generator/terms.py`). Define a concept there, once, and include it where it is used; never restate it in a prompt's own words, and prefer a field the model fills (a kind, a being, `if_broken`) that Python acts on over a sentence of exceptions. Cast seeds carry `being`, which decides who `names.py` names (the role-reading regexes are the fallback for older files).

`prompts/s*.prompt` are the real product. Each demands JSON-only output with a fixed key shape. Extraction prompts carry `evidence_basis` from the five-tier set `explicit → strong_inference → genre_association → mixed → no_signal`; construction prompts carry `serves`. Every prompt that takes an optional upstream JSON tolerates the literal string `none`. The phase-3 prompts end with a REASONING DISCIPLINE block; it has no measurable effect on this model and the newer prompts do not carry one.

**Read `docs/step3_consolidated_design_lessons.md` before drafting or editing any prompt** (§6a–§6d carry the pipeline-level patterns), and `docs/outline_design.md` §6 for the JSON shapes `outline.py` depends on — changing a step-4 prompt's schema means changing `schemas.py`, the validator, the stub, and usually `checks.py`.

Rules that apply pipeline-wide: **generation and verification never share a prompt**; **repair is a separate call that receives the violation list and returns only what it changed**; **a prompt receives the brief or a packet, never the bundle**; **the question is not the verb** (a story decision is reached through play, never offered as a menu); **counts, lookups and structural checks are computed**; **calibration examples are domain-separated from the test kernels in judgment shape, not just nouns, and obey their own prompt's rules** (kernel1 is never an example; the live example stories are the travelling circus (3.5a/b/c) and the string quartet (3.5a), the dig (3.5b Example B, 4c, 4p), the theatre company (4a, 4b, 4d), the samurai story and the jury room (3.4), and the late-night radio phone-in (5a0-5a2), none of which may resemble a test kernel in shape; **examples carry stakes in bodies, places, weather and things, not paperwork** (and `generator/paper.py` counts it where story material is written: 3.5a's engine and 3.5b's ways soft-reject past a quarter on paper, two more when the Kernel names a document; the premise audit makes it a craft finding; 4b soft-rejects summaries the same way): on 2026-10-04 70-100% of node summaries on most kernels turned on documents, fees and signatures, traced to examples built on loans, contracts, permits and entry forms (`evaluate.py` paperwork_share measures it)); **promises are defaults, never constraints**; **the story's own words**: a phrase of the brief's analytic text is never carried into the engine as a thing in the world.

Iteration workflow: run `tests/test_plumbing.py` → draft or edit the prompt → **run the step's saved cases** (`python steptest.py` in `generator/`: `tests/steps/premise_audit/` holds past false alarms and true positives for 3.5v with what must and must not be found; about 6 minutes a case, `--no-think` about 1, `--kernel-only` runs just 3.5k; a verified Kernel contradiction no case expects counts as a false alarm in every case) → run against real kernels → read the full thinking trace and `report.py`, not just the JSON → fix the cause, not the case: a new failure becomes a new step case before it is fixed → check the held-out kernels (`tests/kernels/HELDOUT.txt`: never debugged against, run only at milestones, `batch.py add --set heldout`). `docs/fable_response_4.md` §9 lists what has never been run against a live model.

## Other files

- `tests/test_plumbing.py` — stub-driven tests: every stub scenario, the graph invariants, the Ollama client against a fake server. Keep `generator/stub_client.py` in sync with any schema change; the test fails if a prompt in `prompts/` is exercised by no scenario.
- `tests/kernels/kernel*.txt` — the test kernel batch (input fixtures, not automated tests). Rich story kernels: 1, 2, 3, 5, 31, 33 (romance), 34 (court intrigue, an antagonist plan that advances on its own), 35 (funny and frightening ghost story), 36 (snowbound horror with a group), 37 (a crew heist with a traitor), 38 (Victorian country-house murder), 39 (ancient Rome), 40 (frontier West). Sparse: 6, 7, 8 (no signal), 32. Phase-3 edge cases (contradictions, two themes, viewpoint and timeline tricks): 10-15, 20-22, 24, 26, 27, 29, 30. Shape and adversarial: 4 (loops, hard failure), 16 (a clock), 17 (linear with many endings), 25 (clue memory), 28 (no crime). `retired/` holds 9, 18 and 23 (duplicates). `EVAL_SET.txt` is the full evaluation set (1, 5, 8, 17, 28, 31, 32, 34, 35; two nights), `EVAL_QUICK.txt` the one-night subset (1, 31, 34, 35); `ab.py --kernels eval|quick`.
- `generator/report.py`, `generator/probe_ollama.py` — run statistics against a baseline; capability probe of the local server. `generator/evaluate.py`, `generator/ab.py` — computed outline metrics and the A/B harness. `generator/batch.py` — the batch queue (stories/batch_queue.json): runs jobs in order under a machine-wide GPU lock (`../.stratum_gpu.lock`, shared by every copy of the code), re-queues jobs a kill left running, retries a transient failure once, reports times, outcomes and metrics. Use it for every model run so two runs never share the GPU. `generator/playtest.py` — walks a story graph as players would (every playthrough, walkthroughs per ending, reachability, dead ends, unwalkable lines; and for stage A, options with state effects, play styles and pattern-shift checks): `python playtest.py <story_id|path> --walkthroughs`. `generator/errors.py` — `SoftReject`, `PipelineHalt`.
- `engine/` — the stratum engine (moved here from the mothballed `stratum-if` repository): a data interpreter for a story package (`stratum-story/1`: rooms, objects, characters with topics, scenes with interactions, events, nudges and exits, arc states, endings with composed resolutions). `expressions.py` (the safe condition language, with `pattern()` for arc states), `state.py`, `story.py` (loading and the static validator), `runtime.py` (the menu tree verb → object → detail, actions, rewind, save/load), `cli.py` (the plain terminal player: `python engine/cli.py engine/examples/kernel35_demo.json`, `--check` to validate; `h` history, `u` unwind, `j` journal), `tui.py` (the paned curses interface, `engine/ui/`: story, menu with arrow keys, a Here panel, journal, history, help; `--keys` for scripted play), `recap.py` (the journal, shared by both), `playtest.py` (every reachable state plus simulated players: stuck states, missed opportunities, pattern-shift rates, walkthroughs; `python engine/playtest.py <package> --walkthroughs`; stage D's check). Engine modules import as siblings, like the generator's. `docs/engine_design.md` is its design; `tests/test_engine.py` its tests (no model, about 25 seconds).
- `generator/names.py`, `config/names.json` — cast names assigned in Python after 3.5c (deterministic per story id); prompts keep naming people by role, which stays the matching key. 20 pools picked by genre cues (fantasy, medieval, modern, scifi, period, romance, adventure, regency, victorian, western, age of sail, ancient Greek/Roman/Egyptian, Norse, Japanese and Chinese historical) with per-culture styles (single names, "X of Corinth", Norse patronymics, Roman tria nomina, family name first), a per-character override for elves, dwarves and orc-kind named in the role, and the gender the cast step states (`gender` f/m/n) before any pronoun guessing.
- `stories/current_output.tar` — the archived kernel1 run on the 2026-09-29 pipeline (the one this outline loop replaced): through 3.5–3.7 and about two step-4 iterations of node builds, 31.7 hours, with full thinking traces. `docs/baseline_kernel1_run_stats.json` is its per-call timing, rebuilt from its log timestamps.
- `prompts/later/`, `generator/later/` — parked later-stage material (craft spine, cast, world, node build, review). Not loaded or imported. See `prompts/later/README.md`.
- `docs/fable_strategy_review.md`, `docs/fable_request_2..5.txt`, `docs/fable_response_3.md` — the external review and the requests and responses of earlier passes. `docs/run_samples/<date>/` holds real local-model outputs (outline, brief, premise, audit loop, run stats) for review without a model; its README says which code produced each and what we thought of it.
